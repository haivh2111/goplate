# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Current state

This repo is **specification-only** right now. The single file [CLI_SPEC.html](CLI_SPEC.html) describes the `goplate` CLI that has not yet been implemented. Before assuming a file, package, or command exists, check the filesystem — most of what the spec describes is still to be built.

When implementing, treat the spec as the source of truth: command names, flag names, generated file layout, and conventions in [CLI_SPEC.html](CLI_SPEC.html) are the contract.

## What `goplate` is

A Go CLI with two distinct responsibilities — the implementation must keep them separate:

1. **Project bootstrapping** (`goplate new <name>`) — clones the `go-rest-api-boilerplate` template, rewrites the Go module path, copies `.env.example` → `.env`, runs `go mod tidy`. Run *outside* a project.
2. **In-project code generation** (`new-feature`, `new-adapter`, `new-event`) — scaffolds files into an existing project that follows the boilerplate's layout. Run *from a project root*; also exposed via `make gen-feature|gen-adapter|gen-event` shims in the generated Makefile.

`goplate doctor` checks the host has Go 1.22+, git, air, swag, mockery, golangci-lint. `--fix` should `go install` anything missing.

Entry point binary lives at `cmd/goplate/`. Install path is `github.com/haivh2111/goplate/cmd/goplate@latest`.

## Architecture the generator must produce

Generated projects follow **Folder-by-Feature + Ports & Adapters**. The dependency direction is enforced — generated code must never violate it:

```
handler.go → service.go (iface) → service_impl.go → repository.go (iface) → repository_mysql.go → GORM
                                       ↓
                          adapters/<svc>/port.go (iface) → adapters/<svc>/<provider>/adapter.go
```

**Golden rule the generator enforces:** a `features/<name>/` package may import *interfaces* from `adapters/<svc>/` but never a concrete provider package (e.g. `adapters/payment/stripe`). The wiring of concrete implementations happens only in `cmd/main.go` and the `Providers` struct.

Per-feature file set generated by `new-feature` (under `internal/features/<name>/`):
`model.go`, `repository.go`, `repository_mysql.go`, `service.go`, `service_impl.go`, `dto.go`, `handler.go`, `module.go`, plus `*_test.go` siblings. `module.go` owns DI wiring and route registration; the user must still register the module in `internal/server/server.go` and add the model to `internal/infra/database/migrate.go` (the CLI prints these next steps).

Per-adapter set generated by `new-adapter <svc> <provider>` (under `internal/adapters/<svc>/`):
`port.go` (the interface that features depend on) plus `<provider>/adapter.go` and `<provider>/adapter_test.go`. The constructor pattern is `NewAdapter(...) <PortInterface>` — concrete types are unexported.

`new-event` mutates `internal/events/event_types.go` (appends a constant + payload struct) and appends a handler to `internal/features/<subscriber>/subscribers.go`. It is the only generator that edits existing files rather than creating only new ones; preserve idempotency.

## Conventions the generator must follow

- Package names: lowercase, no underscores (`user`, `stripe`).
- Interfaces: plain nouns (`UserService`, `PaymentGateway`).
- Constructors: `New<Type>` returning the interface, not the struct.
- Errors: generated code returns `shared.AppError` helpers (`ErrNotFound`, `ErrConflict`, `ErrForbidden`, `ErrBadRequest`) — never raw `errors.New` in service layers. Handlers `return err` and let middleware map to HTTP.
- Responses: `shared.OK(data)` / `shared.Created(data)` — no raw `c.JSON` in handlers.
- All handlers must have full Swagger annotations; all DTOs must have `validate:` tags.
- Coverage floor is **≥80%** per package — generated `*_test.go` files must be table-driven skeletons that compile and pass on day one.

## Commands

There is no Go toolchain to invoke yet. Once `cmd/goplate/main.go` exists, expect:

```
go build ./cmd/goplate          # local binary
go install ./cmd/goplate        # install to $GOPATH/bin
go test -race -count=1 ./...    # standard test invocation
make install                    # alias for go install (per spec)
```

Generator commands should all support `--dry-run` (preview without writing) — this is non-optional in the spec.

## Field-spec mini-DSL

`--fields` (feature) and `--payload` (event) take comma-separated `name:type` pairs:
`"name:string,price:float64,active:bool,stock:int"`. Implementation must map these to GORM column types, JSON tags, validator tags (e.g. `float64` → `gt=0` default), and Swagger types in one pass. Keep the parser shared between `new-feature` and `new-event`.
